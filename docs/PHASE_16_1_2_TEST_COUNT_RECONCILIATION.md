## 2. Root Cause of the Historical 407 Discrepancy

The historical 407 count originated from a **static source code regex query** (`/test\s*\(/g` and `/it\s*\(/g`) across `.ts` files rather than inspecting runtime test runner output:

1. **Nested Node.js Subtests (`t.test(...)`)**:
   Under the Node.js native test runner (`node:test`), top-level test blocks that invoke `await t.test(...)` count the parent test *and* each subtest in the runner totals. Static source queries missed nested subtests or counted parent/child relationships inconsistently.
2. **`describe` / `it` Suites in Phase-Specific Suites**:
   Files utilizing standard BDD constructs had nested cases that were undercounted:
   - `tests/phase10b-ecommerce.test.ts`: Actual runtime tests = **15** (static count misreported 8).
   - `tests/phase13-security.test.ts`: Actual runtime tests = **19** (static count misreported 14).
   - `tests/phase14-1-2-fallbacks-statistics.test.ts`: Actual runtime tests = **11** (static count misreported 7).
   - `tests/phase15-1-reliability.test.ts`: Actual runtime tests = **14** (static count misreported 9).
   - `tests/phase15-visual-editor.test.ts`: Actual runtime tests = **12** (static count misreported 8).
3. **Execution Verification**:
   When each file is executed individually via `npx tsx --test <file>`, the individual test counts sum **exactly to 444**, matching the combined `npm test` single-run summary to the exact integer.
